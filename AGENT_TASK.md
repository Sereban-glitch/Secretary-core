# Задание: довести Secretary Core до подключаемого модуля

## Назначение
Основной первый потребитель — админка сельскохозяйственного бота: технические отзывы на русском/украинском. Далее другие боты. Не зашивать бренды, имена людей, Telegram, ID клиентов или конкретную БД в ядро. Предметный словарь и язык передавать параметрами.

## Этап 1 — надёжная расшифровка
1. Python 3.12+, ffmpeg/ffprobe; переиспользовать полезные идеи из docs/HISTORY.md, не старые секреты и глобальные каталоги. Минимум зависимостей; версии фиксировать.
2. Локальные MP3/M4A/OGG/WAV: проверка действительного формата, размера, длительности; отдельная папка на job; SHA256 исходника. ffmpeg без shell=True, лимиты времени/диска/памяти. Последовательный тяжёлый worker по умолчанию.
3. Длинное аудио разбивать на сегменты; сохранять временные границы, статус и результат каждого. Продумать перекрытие границ без дублирования фраз. Не выдавать модельные временные отметки за измеренные.
4. Прокси через отдельный транспорт, URL/ключ/модель из конфигурации. Таймаут, bounded retry для временных ошибок, backoff/jitter, Retry-After, отмена. Нет обхода квот или смены аккаунтов. Не повторять permanent ошибки бесконечно; HTTP 200 с ошибкой/пустым ответом не успех.
5. Перезапуск продолжает незавершённые сегменты. Ошибка части даёт partial/failed, НЕ completed. Хранить версию профиля/модели/промпта, не смешивать результаты разных заданий. Idempotency с учётом параметров, не только хеша файла; изоляция пользователей.
6. Транскрипт сохранять полно и близко к исходнику. Неразборчивое помечать, не выдумывать имена/цифры. Имена спикеров только при наличии подтверждения, иначе нейтральные метки. Не вырезать «бытовые» части автоматически.
7. Структурирование отдельным шагом: summary, темы, утверждения, сомнительные места, ссылки на сегменты. Полная расшифровка неизменна; редакторский текст не заменяет источник. Никаких неподтверждённых заявлений о точности.

## Этап 2 — подключение и импорт
- CLI + небольшой документированный HTTP API либо иной обоснованный адаптер: create/status/cancel/result. Выбрать простое постоянное хранилище задач, добавить миграции и тесты восстановления.
- Результат версии v1: job_id, status, source {filename, sha256, mime, duration}, segments [{id,start,end,status,text,warnings}], transcript, structured_draft, warnings, provenance. JSON Schema и примеры на вымышленных данных; политика хранения/очистки отдельно от публикации.
- Выдавать JSON/Markdown; публикация в базу только на стороне клиента после подтверждения. Пример адаптера AgroBot без его кода/ключей; можно отдельный HTTP клиент с mock.
- ZIP-импорт как отдельный слой: allowlist типов, лимит числа/распакованного объёма/коэффициента сжатия, запрет traversal/симлинков/вложенных архивов, потоковая запись, общий манифест. Документы передавать существующему обработчику клиента, не изобретать внутри транскрибатора второй редактор базы.
- Ссылки Google Drive — следующий необязательный этап. Для URL нужны защита от SSRF и редиректов во внутренние сети, проверка прав, лимиты скачивания. Закрытые материалы не делать публичными автоматически.

## Проверки и приёмка
- Offline: запрос/ответ прокси, malformed/empty/truncated response, 429/5xx, таймаут/отмена, возобновление, частичная ошибка, два задания без смешивания, отсутствие секретов в логах, архивы с traversal/бомбой, неподдерживаемые типы.
- Интеграция: ffmpeg на синтетическом аудио; после разрешения — одна короткая реальная запись через прокси. Статус completed только после полного успешного покрытия сегментов.
- Реальный приёмочный архив владельца содержит 3 документа и 5 аудио; в публичный репозиторий он не включён. Воспроизвести такую структуру синтетически. Позже владелец предоставит приватный набор и эталон для ручной проверки имён/моделей/чисел.
- Отдать код, тесты, команды запуска, описание API, ограничения, простой пример подключения, HANDOFF.md с выполненным/непроверенным и следующим шагом. Запуск на малой VM около 1 ГБ согласовать отдельно, нагрузку на production не создавать.

## Свобода решений
Можно улучшать интерфейсы, наблюдаемость и UX прогресса. Не расширять проект до нового бота/платформы, не менять провайдера без согласования. Объяснять важные решения коротко, не обещать 100% точность. Сначала исправная изолированная обработка, затем дополнительные удобства.
