# OWNER-GUIDE-RU.md — как проверить одну настоящую аудиозапись

Это инструкция для владельца. Простыми словами, без лишней техники.
Все команды выполняются в вашей среде, где доступен ваш приватный прокси.
Ничего не публикуется в AgroBot и не отправляется в GitHub — этой
проверки эти системы вообще не касаются.

## Что понадобится

1. Распакованный архив проекта (ZIP прохода 5) и установленные
   ffmpeg и ffprobe (бесплатные, обычно уже есть).
2. Одна короткая аудиозапись: 2–5 минут обычной речи. Подходят форматы
   mp3, m4a, wav, ogg, flac и похожие.
3. Позже, для живого теста: адрес вашего прокси, имя модели и ключ —
   те же настройки, что использует ваш секретарь. Передавайте их только
   через файл настроек на вашей машине, не в чате.

## Шаг 1. Проверка готовности (1 команда)

Из папки проекта выполните:

```
python3 examples/proxy_check.py doctor --dest data/proxy-check
```

Прочитайте список строк. Напротив каждого пункта стоит OK или FAIL.
В конце две строки: «dry-run: ГОТОВ/НЕ ГОТОВ» и «live: ГОТОВ/НЕ ГОТОВ».
Dry-run должен быть ГОТОВ сразу (нужен только ffmpeg). Live станет
ГОТОВ, когда вы добавите настройки прокси (шаг 3). Если FAIL — в строке
написано, чего не хватает.

## Шаг 2. Безопасный прогон без сети (1 команда)

Положите запись, например `zapis.mp3`, рядом и выполните:

```
python3 examples/proxy_check.py run zapis.mp3 --dest data/proxy-check
```

Это «сухой» прогон: запись обрабатывается по-настоящему (нарезка,
конвертация), но вместо вашего прокси отвечает подставной отвечальщик,
сеть не используется вообще. Он доказывает, что всё остальное работает.
Появится итог («complete» — хорошо) и два файла: `report.json` и
`report.md`. Если в архиве несколько аудио — утилита попросит уточнить,
какое именно (добавьте `--select имя_файла`).

Для специализированной речи можно сразу передать язык и словарь терминов:

```
python3 examples/proxy_check.py run zapis.mp3 --dest data/proxy-check \
  --language uk --vocabulary-file profiles/horsch-uk-ru.txt
```

Словарь — обычный UTF-8 файл: один термин на строку, строки с `#` считаются
комментариями. Также можно дописать несколько терминов прямо в команде:
`--vocabulary "HORSCH,LEEB,обприскувач"`.

## Шаг 3. Живой тест через ваш прокси (1 команда, только по готовности)

Когда решите проверить по-настоящему:

1. Создайте в папке проекта файл `secretary.env` (права только для
   владельца) с тремя строками:
   ```
   SECRETARY_PROXY_BASE_URL=адрес_вашего_прокси
   SECRETARY_PROXY_API_KEY=ваш_ключ
   SECRETARY_MODEL=имя_модели
   ```
2. Выполните:
   ```
   SECRETARY_LIVE_CONFIRM=1 python3 examples/proxy_check.py run zapis.mp3 --dest data/proxy-check --env-file secretary.env --live --live-yes
   ```

Здесь два подтверждения сразу (переменная + флаг) — это защита от
случайного запуска. Если что-то из них забыть, утилита откажется
работать и ничего не отправит.

Важно про длинные записи: в живом режиме программа сама, локально,
вырезает короткий кусок записи — по умолчанию первые 60 секунд — и
отправляет в прокси ТОЛЬКО этот кусок. Даже если запись многочасовая,
наружу уйдёт лишь маленький фрагмент. Длину можно поменять, например
30 секунд: добавьте `--live-fragment-seconds 30` (разрешено от 1 до
600 секунд). Исходный файл при этом не изменяется. Проверить живым
режимом можно только одну запись за раз.

## Что вы получите

- `report.md` и `report.json` — понятный итог: время по этапам, пиковая
  память, статус расшифровки, длительность записи, размер и контрольная
  сумма файла. Текста расшифровки в них нет совсем — ни одного символа.
- Папка `review-<номер запуска>` — полный текст расшифровки и полная
  опись материалов с контрольными суммами каждого файла. Она закрыта
  правами доступа: файлы читает только владелец. Ключ и адрес прокси
  в отчёт не попадают никогда.
- Ничего не уходит в AgroBot: у утилиты нет с ним связи, в отчёте
  это указано прямо.

Если вам НУЖНО, чтобы текст расшифровки был прямо в отчёте — добавьте
флаг `--include-transcript` к команде run (или replay). Тогда отчёт
сразу закрывается правами «только владелец» и передавать его нужно
осторожнее.

## Если что-то пошло не так

- Прерывание, сбой сети, ошибка прокси — просто выполните ту же команду
  с `replay` вместо `run`, добавьте `--retry-failed`, если в отчёте
  статус «failed»:
  ```
  python3 examples/proxy_check.py replay --dest data/proxy-check --env-file secretary.env --live --live-yes --retry-failed
  ```
  Утилита продолжит с места сбоя, а не начнёт с нуля.
- Статус «failed» в отчёте — это честный результат: он означает, что
  расшифровка не удалась, а не «всё в порядке». Так и задумано.

## Что делать с результатом

Передайте проверяющему `report.json` и `report.md` (они обезличены).
Полный текст расшифровки из папки review-… передавайте, только если
сами считаете нужным — это содержимое вашей записи.
