# Secretary Core — независимый умный расшифровщик

Публичная чистая основа для внешнего агента. **Модуль подключаемого
расшифровщика прошёл первый живой тест через приватный loopback-прокси
23.09.2026.** Нет зависимости от Telegram, AgroBot, его БД или секретов.
Цель: аудио/видео → речь, надписи и видимые события → структурированный черновик →
проверка человеком → экспорт в любую базу знаний.

Начать с [задания агенту](AGENT_TASK.md), [контракта прокси](docs/PROXY.md),
[инструкции подключения](docs/INTEGRATION.md), [предыстории](docs/HISTORY.md)
и [HANDOFF.md](HANDOFF.md) (выполнено / проверено / не проверено).
Проверку одной живой записи в среде владельца описывают
[OWNER-GUIDE-RU.md](OWNER-GUIDE-RU.md) (простыми словами) и
[OPERATOR-GUIDE-RU.md](OPERATOR-GUIDE-RU.md) (полные команды).

## Сейчас реализовано

- Видео-MVP: MP4/MOV/WebM проверяются, делятся на короткие MP4-фрагменты,
  мультимодальная модель извлекает речь, надписи, события с таймкодами
  и факты с меткой источника audio/visual/both. Исходник по умолчанию удаляется
  после успеха; в базу знаний ничего не публикуется без проверки человеком.

- Полный конвейер (Python 3.12+, stdlib only): валидация MP3/M4A/OGG/WAV
  (сигнатуры + ffprobe), SHA256, отдельная папка на job, сегментация с
  перекрытием и дедупликацией стыков, ffmpeg без shell с таймаутами и
  rlimits.
- Транспорт к настраиваемому прокси: bounded retry (backoff/джиттер/
  Retry-After), классификация временных/постоянных ошибок, HTTPS-only
  для удалённых, без редиректов, ключ не попадает в логи.
- Постоянное хранилище задач (SQLite, миграции, восстановление после
  перезапуска, идемпотентность с учётом параметров, изоляция владельцев).
- Полный транскрипт дословно + отдельный структурированный черновик
  (summary/темы/утверждения/сомнительные места со ссылками на сегменты);
  `completed` только при полном покрытии сегментов.
- CLI и документированный HTTP API (create/status/cancel/result/
  markdown/retry-failed), ZIP-импорт с защитой (allowlist, лимиты,
  traversal/симлинки/вложенные архивы), JSON Schema результата v1.
- Потоковая HTTP-загрузка: тело пишется на диск кусками по 1 МиБ, в RAM
  не держится ничего (целевая VM ~1 ГБ); chunked-тело не поддерживается.
  Bind не на loopback без `SECRETARY_API_TOKEN` запрещён на старте;
  внутренние ошибки (500) не раскрывают деталей клиенту.
- Allowlist документов ZIP-импорта синхронизирован с реальной админкой
  AgroBot (pdf, docx, pptx, xlsx, doc, ppt, xls, txt, md, csv, json,
  jpg, jpeg, png, webp) — приёмочный состав Хорш.zip (PDF+PPTX+DOCX +
  4 MP3 + 1 M4A) проходит целиком.
- Пример подключения AgroBot без его кода/ключей: адаптер, клиент с
  реальным контрактом авторизации (`tma <URL-encoded initData>`,
  initData — кратковременные, не сервисный токен) и оркестратор полного
  приёмочного сценария (документы и аудио из ZIP — раздельные потоки,
  публикация только после проверки человеком) + мок, проверяющий
  подпись HMAC/свежесть/allowlist как настоящий tmaAuth.
- Область действия запуска оркестратора: уникальные run_id/owner на
  каждый импорт; расшифровываются и публикуются ТОЛЬКО job_id из
  манифеста текущего ZIP — старые/чужие задания общей SQLite не
  примешиваются. Отчёт — ТРИ независимых статуса (этапы не смешиваются):
  transcription_status / publication_status (включая
  nothing_to_publish) / итоговый workflow_status, который и задаёт
  коды возврата 0/1/2/3; итог учитывает ВСЕ аудио-задания текущего
  импорта — упавшее/пропавшее/оставшееся в очереди аудио делает
  итог минимум partial, а без единого опубликованного материала —
  failed с ненулевым кодом (ложноположительный «complete» невозможен).
- Загрузка в AgroBot батчами не более 5 файлов и 16 МиБ на запрос
  (как лимиты админки: MAX_FILES_PER_UPLOAD=5, 20 МиБ/файл, рейт-лимит
  10 запросов/мин); живость — по реальному маршруту /api/healthz.
- Утилита проверки одной живой записи `examples/proxy_check.py` (pass5 +
  корректирующий проход): doctor / run (dry-run без сети | live с двойным
  подтверждением SECRETARY_LIVE_CONFIRM=1 + --live-yes) / replay
  (возобновление, в т.ч. --retry-failed) / review-package; в live в прокси
  уходит ТОЛЬКО локально вырезанный короткий фрагмент записи
  (--live-fragment-seconds, по умолчанию 60 с, 1..600); замер RSS
  (self+ffmpeg) с честным «unavailable» без /proc; отчёты без НИ ОДНОГО
  символа расшифровки (текст — только явным флагом --include-transcript,
  тогда отчёт закрывается 0600), с длительностью, sha256, размерами и
  раздельным временем этапов; пакет материалов с описью
  package-manifest.json и правами 0700/0600; к AgroBot не подключена
  вообще. Архив с несколькими аудио требует явного выбора
  (--select/--index/--all).

## Запуск

```sh
python3 -m unittest discover -s tests -t . -v   # 246 тестов, офлайн
python3 -m secretary.cli selftest              # быстрая проверка ядра
python3 -m secretary.cli transcribe file.wav --fake-transport --markdown -o out.md
python3 -m secretary.cli analyze-video lesson.mp4 --markdown -o video.md
python3 -m secretary.cli serve --host 127.0.0.1 --port 8080   # HTTP API + воркер
python3 examples/proxy_check.py doctor --dest data/proxy-check # проверка среды
python3 examples/proxy_check.py run file.mp3 --dest data/proxy-check  # dry-run без сети
```

Если системного ffmpeg нет, но установлен Flatpak runtime 25.08, ничего
доустанавливать не нужно:

```sh
scripts/run-with-flatpak-ffmpeg.sh \
  python3 examples/proxy_check.py run file.mp3 --dest data/proxy-check
```

Проверено на `org.freedesktop.Platform//25.08`, FFmpeg 7.1.3. Другую версию
можно указать через `SECRETARY_FFMPEG_FLATPAK_RUNTIME`.

Если запись не проходит через лимит Telegram, её можно забрать по публичной
HTTPS-ссылке или ссылке Google Drive (по умолчанию до 512 МиБ):

```sh
python3 -m secretary.cli fetch-url \
  'https://drive.google.com/file/d/FILE_ID/view?usp=sharing'
```

Загрузка потоковая: файл не помещается целиком в RAM. Проверяются адрес,
перенаправления, размер и свободное место; незавершённый файл удаляется.
Для Google Drive достаточно доступа «все, у кого есть ссылка».

Конфигурация указана в `.env.example`. Рабочий прокси приватный: доступ
выдаёт владелец отдельно. Без него использовать fake transport
(`--fake-transport`); не заменять его прямыми платными API молча.
Реальная расшифровка одной контрольной записи проверена; публикация в
AgroBot и длительные массовые прогоны пока не проверялись — точный список в
[HANDOFF.md](HANDOFF.md). Лицензию на распространение отдельно определяет
владелец; сейчас лицензия не назначена.

Для украинско-русских отзывов HORSCH проверен профиль:
`--language uk --vocabulary-file profiles/horsch-uk-ru.txt`; из доступных
маршрутов лучший результат на контрольной записи дала модель
`gemini-3.7-flash-tiered`. Публикация результата по-прежнему требует
проверки человеком.
