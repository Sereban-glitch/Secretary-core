# Контракт прокси: наблюдения и границы

18.09.2026 просмотрен установленный у владельца antigravity-claude-proxy, конвертер `src/format/content-converter.js`. Это статическая проверка, НЕ подтверждение успешного аудиозапроса.

Планируемый endpoint: POST `${SECRETARY_PROXY_BASE_URL}/v1/messages`, Anthropic-подобный JSON. Model и способ авторизации проверить на предоставленном экземпляре; не выбирать случайное имя модели. Никакие реальные адреса/токены здесь не хранятся. Base URL задаётся без `/v1`.

В просмотренном конвертере ветки `type: audio` нет. Ветка `type: image` + source.type=base64 преобразуется в Gemini inlineData с сохранением source.media_type, в том числе audio/ogg. Это специфический транспортный адаптер данного прокси, НЕ универсальный стандарт API и НЕ изменение MIME аудио на картинку. Текущий payload builder отражает этот код; реальный end-to-end запрос обязателен перед production. При смене прокси адаптер заменить и протестировать отдельно.

Запрос содержит model, max_tokens, stream:false, messages/user/content: текст инструкции + транспортный блок base64 с настоящим аудио MIME. Ответ ожидается content[{type:text,text}], stop_reason. При max_tokens — результат усечён, не успешен; пустой/ошибочный ответ отвергать.

Сетевого клиента в starter ещё нет. Не отправлять ключи в URL/логи, не ходить по произвольным redirect, требовать HTTPS для удалённых соединений (loopback допускается отдельно), не публиковать прокси наружу ради внешнего агента. Агент разрабатывает на mock, владелец позже запускает интеграционную проверку внутри своей инфраструктуры.
